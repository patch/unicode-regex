# Structured data

50 languages, 30 providers, 48 support mappings and 31 additional library relationships, plus Unicode feature research. Open [Unicode Regex.base](Unicode%20Regex.base) for the survey and Unicode research views.

- `Languages/<id>.md`: `record_type: language`, `name`, quoted `version`, `tiobe_rank`, `tiobe_rating`; optional `version_source`, `support_status`, `providers` list, `notes` and `sources` list. Named releases without a single version source use `sources`.
- `Providers/<id>.md`: `record_type: provider`, `name`, `provider_type`, `documentation`, `rank`, `score`, and lists `ranking_language_syntax`, `ranking_included_api`, `ranking_add_on_library`; optional booleans `iuc38`, `utw2026` and `inactive`, `additional_libraries` list of Library IDs, `library_notes`, `library_sources` and `sources` lists.
- `Support/<language>-<provider>.md`: `record_type: support`, `language`, `provider`, `category`, `sources`; optional `api`, `implementation`, `targets` list and `notes`. Append a target to the filename if a pair needs separate records.
- `Libraries/<language>-<provider>.md`: `record_type: library`, `language`, `provider`, `name` (package/library), quoted `version`, ISO `release_date`, `sources`; optional ISO `maintenance_date` and `notes`. Dates may be quoted or saved as native YAML dates by Obsidian. One representative qualifying add-on per language/provider pair.

Language and provider filenames supply stable IDs; change `name` for display-name edits. Renaming an ID requires updating every reference. Support references use those IDs; Bases supplies clickable links. Read relationships from properties, not by splitting filenames. Keep properties flat, one per line; use lists for sources and targets. Store qualifications as plain text in `notes`, displayed in the corresponding view, with URLs in source properties. Record bodies are empty. Missing targets or implementation means no restriction was recorded.

Each view selects its record folder. Bases locates the dataset through the unique filename `Unicode Regex.base`, so the views and links keep their scope when embedded elsewhere or opened in a sidebar. Keep that filename unique within the vault.

Use **New** in the corresponding view, complete the editable properties and right-click **ID** → **Rename…** to set the filename using the conventions above. **Language ID** and **Provider ID** in Support are editable references; the Language and Provider columns display their names. New records remain incomplete until all required data and affected display/ranking fields are updated.

Language `providers` lists are derived display indexes of provider IDs, ordered by provider rank. Support records remain authoritative; keep these lists in sync when mappings change. The Languages view displays the provider names as links alongside each language.

Categories: `Language syntax`, `Included API`, `Add-on library`. Included API covers bundled language, runtime and platform APIs. Add-on libraries qualify only when named in official language/project documentation. Language `support_status` is present only for `None documented` (no qualifying provider identified) or `Unspecified` (support varies across implementations). The Languages view shows `Documented` when its providers list is populated; incomplete entries without a status or providers display a blank.

Provider types: `Engine` identifies an implementation or library; `API family` identifies an API whose engine is unidentified or variable; `Standard family` identifies a standardized facility with multiple implementations. Wrappers are grouped under their documented underlying engine. Libraries with their own implementations remain separate even when they share syntax.

Provider `inactive: true` marks documented discontinued or unmaintained upstream providers, with evidence in `sources` or `library_sources`. Omitted or `false` means not marked inactive, not a verified active status. This flag does not affect ranking or scoring; exclusion from the additional-library survey alone does not establish inactivity.

Provider `iuc38: true` marks coverage in the [IUC38 provider comparison](IUC38/Slide%2016.md); omitted or `false` means not covered. Slide labels Python, Java, JavaScript and ICU4C correspond to Python re, java.util.regex, ECMAScript RegExp and ICU.

Provider `utw2026: true` marks a provisional research candidate for [UTW2026](UTW2026/README.md); omitted or `false` means outside the current shortlist. Final presentation coverage may be narrower.

Ranking month: `2026-10`. Language versions checked: `2026-10-19`. Support mappings checked: `2026-10-20`.

Versions are the latest stable releases or published standards at the check date. Family-wide entries retain their scope and state when no single version exists. Provider mappings use documentation for those versions; historical-only mappings are excluded.

Ranks are integers; TIOBE ratings and provider scores are numeric percentage points. Each language contributes its full rating once to each associated provider, including conditional or optional support. Ratings are not split; missing or unspecified providers are excluded. Scores measure language exposure, not normalized usage shares.

Provider order uses total score descending, then rating subtotals for Language syntax, Included API and Add-on library, in that order. Each language/provider pair uses its strongest category. Providers equal on all four values share a competition rank (1, 2, 2, 4); alphabetical order arranges tied rows. Languages within each category list follow TIOBE rank order.

Provider ranks, scores and category lists are stored snapshots. Bases does not recalculate them automatically; keep them consistent when mappings or ratings change. Provider comparison displays these fields, while Support displays the individual relationships.

Additional libraries checked: `2026-10-22`. Survey scope: maintained, reusable implementations of ICU, PCRE2, RE2, Rust regex, Boost.Regex and TRE, limited to the existing language/provider IDs. Oniguruma and legacy PCRE are excluded because upstream maintenance ended; Onigmo is excluded because ongoing maintenance as a standalone reusable library is unclear, despite maintenance of Ruby and Fluent downstream copies. Runtime-specific providers such as Python re are outside this survey. Ports and independent reimplementations are excluded entirely; compiling the original implementation to WebAssembly does not create a new provider.

Library inclusion requires a published non-prerelease version, no explicit alpha/beta/experimental/work-in-progress designation, verified regex operations, and release or substantive maintenance evidence within the preceding 24 months. Published 0.x release series can qualify; this is not a promise of an immutable API. Dependency compatibility revisions count as maintenance; recent stars or automated housekeeping alone do not. Older source releases retain their dates and visible qualifications. Both provider and binding must remain maintained. Native installable libraries also qualify; generic FFI or JVM/.NET interoperability alone does not establish additional language bindings. Absence means not verified, not unavailable.

Support's `Add-on library` category remains the formal-language-documentation dataset. Libraries supplies additional package-documented availability without changing Support, Language `providers`, or any ranking input. Package registries and library documentation do not by themselves satisfy the formal-language-documentation rule. Provider `additional_libraries` is a derived list of Library IDs in TIOBE language order; comparison cells link to the evidence records. Keep qualifications and exclusions visible in `notes` / `library_notes`, with URLs in the corresponding source lists.

Run `ruby scripts/check_data.rb` after editing records or views. It checks required properties, types, IDs, references, duplicate relationships, display lists, library release/maintenance dates, category membership and order, scores and competition ranks. The check is read-only; incomplete records fail validation.

## Unicode feature research

Workflow: [Research Plan](Research%20Plan.md). Shared requirement reminders: [UTS #18 reference](UTS18.md).

Baseline: [UTS #18 revision 25](https://www.unicode.org/reports/tr18/tr18-25.html), dated `2025-01-16`. Documentation-only research checked `2026-10-22`: Python re `3.15.1`, Python regex `2026.9.29`, java.util.regex `27.0.1`, .NET `10.0.13`, PCRE2 `10.49` and ECMAScript RegExp `2026` (ECMA-262 edition 17). Python and Java language records were refreshed to `3.15.1` and `27.0.1`; the earlier language-survey date above still describes the other records.

- `Features/<id>.md`: `record_type: feature`, `name`, `sort_order`, `sections` list, `role`, `scope`, `notes`, `sources`; optional `requirement` and `required_properties` list. UTS #18 organizes independently assessable capabilities. `scope`: `Regex` or `Host`; host workflows have their own features. `role`: `Requirement`, `Detail`, `Guidance`, or `Optional`. Roles and requirement references locate the topic in UTS #18; they do not turn a capability status into a conformance finding.
- `Evaluations/<provider>-<feature>.md`: `record_type: evaluation`, `provider`, `feature`, `status`, `mechanism`, `syntax` list, `notes`, `sources`; optional `uts_notes` and `undocumented_syntax` list. One documentation assessment per provider/feature. `status`: `Supported`, `Partial`, `Unsupported`, or `Undocumented`; `mechanism`: `Engine`, `Host API`, `None`, or `Undocumented`. Supported means the named capability is documented. Partial requires a documented functional limitation; uncertainty about UTS alignment belongs in `uts_notes`. If the capability's full scope is unknown, use Undocumented and describe the known subset. Unsupported needs explicit documentation or a grammar that rules out the facility; absence alone means Undocumented. Every reviewed provider must have a result for every feature.
- `Properties/<provider>-<id>.md`: `record_type: property`, `provider`, `name`, `aliases` list, `value_type`, `values` list, `inventory_scope`, `sources`; optional `domain`, `data_sets` list and `notes`. `domain` defaults to `Code point`; use `String` for sequence properties. `value_type`: `Binary`, `Enumerated`, `Numeric`, or `Set membership`. Each values item preserves one published named value followed by its aliases in square brackets; an optional descriptive label in parentheses gives its meaning without asserting an accepted alias. `data_sets` preserves source combinations for set-valued properties; these combinations are not asserted to be accepted combined regex selectors. Empty values means no list was supplied. Omission is not a negative support finding. Common freshness qualifications live on the provider and appear beside each property in Bases.

Reviewed providers additionally have quoted `unicode_review_version`, `unicode_version` (provider's supported/claimed Unicode version), ISO `release_date` and `unicode_review_date`, `unicode_scope`, `unicode_claim`, `property_summary`, `property_inventory_notes`, `unicode_notes`, and a `unicode_sources` list. Optional `unicode_host_version` describes host lookup/preprocessing data where relevant. Optional ISO `property_inventory_date` dates the published inventory, not separate README additions. Use it only when a common date applies to the provider's published-list records; otherwise preserve differing dates in property `notes` and provider inventory qualifications. These describe the latest stable release at the review date. Assess support across all documented options; flags do not reduce support to Partial. Put necessary options in `syntax`, relevant defaults in `notes`, and omit version-mode flags when the feature works in both modes. Published conformance claims remain separate; retain their UTS revision in `unicode_claim` and mark a missing claim as not found in the reviewed sources.

Shared definitions: [property domains](https://www.unicode.org/reports/tr18/tr18-25.html#domain_of_properties) (§1.2.1) distinguish code-point from string properties; [value types and examples](https://www.unicode.org/reports/tr18/tr18-25.html#codomain_of_properties) (§1.2.2–1.2.3) describe their possible values. Properties records hold the provider-specific metadata; these explanatory concepts are not scored as supported/unsupported features. §1.1.1's normalization guidance is attached to hexadecimal notation.

Syntax lists contain regex patterns or named host/API forms, not executed tests. Explain host escaping only where it changes a Unicode example. Keep undocumented spellings separate. Preserve property lists, aliases, extensions, options and qualifications; family summaries alone are insufficient. Python regex's 94-property inventory is unchanged from its `2019-06-02` revision; preserve it as dated positive evidence, not a complete Unicode 18.0.0 inventory. The release changelog and README establish 18.0.0; the generated HTML manual's older 17.0.0 statement is stale.

Open the Unicode reviews, Unicode features, Unicode evaluations, Unicode feature comparison, Unicode host workflows and Unicode properties views. The comparison selects Regex scope, host workflows selects Host scope, and evaluations includes both. UTS alignment notes and inventory qualifications remain visible. The validator checks references, scope separation, complete provider/feature coverage and visible evidence fields. Previous slides are a completeness check, not the taxonomy; slide generation remains deferred.

Ranking source: [TIOBE Index for October 2026](https://www.tiobe.com/tiobe-index/), TIOBE Software BV (www.tiobe.com). Version and support sources are linked in the records.
